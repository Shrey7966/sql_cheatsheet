Day 1 — Foundations
SELECT · Filtering · NULL · Sorting · Date & String Functions
SELECT skeleton
Every query follows this shape. Clause order is fixed.
SELECT col1, col2
FROM table_name
WHERE condition
GROUP BY col
HAVING agg_condition
ORDER BY col DESC
LIMIT 10 OFFSET 0;
💡 Execution: FROM → WHERE → GROUP → HAVING → SELECT → ORDER → LIMIT
Filtering operators
All WHERE clause operators used regularly in SQL.
WHERE salary = 90000
WHERE salary != 90000 -- or <>
WHERE salary BETWEEN 50000 AND 90000
WHERE dept IN ('HR', 'Eng')
WHERE dept NOT IN ('HR')
WHERE name LIKE 'A%' -- starts A
WHERE name LIKE '%son' -- ends son
WHERE name LIKE '___' -- exactly 3 chars
NULL semantics ⚠ TRAP
NULL = unknown. Comparing to NULL always returns UNKNOWN.
-- ❌ WRONG — zero rows always
WHERE salary = NULL
WHERE salary != NULL

-- ✅ CORRECT
WHERE salary IS NULL
WHERE salary IS NOT NULL

-- Replace NULL with fallback
COALESCE(salary, 0)
NULLIF(a, b) -- NULL if a equals b
⚠ WHERE keeps only TRUE. UNKNOWN = row dropped silently.
Top-N pattern INTERVIEW
Get highest or lowest N rows — in every SQL interview.
-- Highest paid employee
SELECT name, salary FROM employees
ORDER BY salary DESC LIMIT 1;

-- 2nd and 3rd highest
ORDER BY salary DESC
LIMIT 2 OFFSET 1;

-- LIMIT n OFFSET m = skip m, take n
Date functions
Extract parts, calculate gaps, format output.
YEAR(d) / MONTH(d) / DAY(d)
QUARTER(d) -- 1-4
WEEKDAY(d) -- 0=Mon, 6=Sun
CURDATE() / NOW()
DATEDIFF(later, earlier) -- days gap
TIMESTAMPDIFF(YEAR,d1,d2) -- any unit
DATE_ADD(d,INTERVAL 30 DAY)
DATE_SUB(d,INTERVAL 1 MONTH)
LAST_DAY(d) -- end of month
DATE_FORMAT(d,'%M %d, %Y')
String functions
Manipulate and format text columns.
CONCAT(first,' ',last)
LENGTH(name)
UPPER(name) / LOWER(name)
TRIM(' Alice ') -- 'Alice'
SUBSTRING(name,1,3) -- first 3 chars
REPLACE(col,'a','b')
INSTR(col, 'word') -- position of word
Extras — DDL & DML
CREATE · DROP · TRUNCATE · INSERT · UPDATE · DELETE · Constraints · Data Types
DDL — table structure
Define and modify table structure.
CREATE TABLE employees (
emp_id INT PRIMARY KEY,
name VARCHAR(50) NOT NULL,
salary DECIMAL(10,2),
dept_id INT
);

ALTER TABLE employees ADD age INT;
ALTER TABLE employees DROP COLUMN age;
DROP vs TRUNCATE vs DELETE ⚠ TRAP
Three very different operations — know the difference cold.
-- DROP: removes table entirely
DROP TABLE IF EXISTS employees;

-- TRUNCATE: all rows gone, keeps structure
-- Faster than DELETE. Resets AUTO_INCREMENT
TRUNCATE TABLE employees;

-- DELETE: removes specific rows only
DELETE FROM employees WHERE emp_id = 5;
⚠ DROP=table gone TRUNCATE=empty table DELETE=rows only
DML — data operations
Insert, update and delete actual rows of data.
-- Insert multiple rows
INSERT INTO employees VALUES
(1, 'Alice', 90000, 1),
(2, 'Bob', 60000, 2);

-- Update specific rows
UPDATE employees
SET salary = 95000
WHERE emp_id = 1;
Constraints & data types
Rules enforced at DB level. Common column types.
PRIMARY KEY -- unique + not null
FOREIGN KEY (col) REFERENCES t(id)
UNIQUE -- no duplicates
NOT NULL -- value required
CHECK (salary > 0) -- custom rule
DEFAULT 0 -- fallback value
ON DELETE CASCADE / RESTRICT

-- Types: INT, DECIMAL(10,2), VARCHAR(255)
-- TEXT, DATE, DATETIME, TIMESTAMP
Day 2 — JOINs & Aggregation
JOIN Types · GROUP BY · HAVING · Aggregate Functions · UNION
JOIN decision rule
Ask these 4 questions before every JOIN you write.
1. What do I want in output?
2. Which tables have that data?
3. Whose rows must never disappear?
→ that table goes in FROM (left side)
4. Are gaps (no match) allowed?
YES → LEFT JOIN
NO → INNER JOIN

-- Never write RIGHT JOIN.
-- Swap table order, use LEFT JOIN.
JOIN types + syntax
INNER = overlap only. LEFT = all left + NULLs for no match.
-- Only matched rows from both sides
FROM employees e
INNER JOIN dept d ON e.dept_id = d.id

-- All left + NULLs where no match
FROM employees e
LEFT JOIN projects p USING(emp_id)

-- Self join: same table, two aliases
FROM employees e
LEFT JOIN employees m
ON e.manager_id = m.emp_id

-- USING = same col name in both tables
-- ON = different col names
Anti-join pattern INTERVIEW
Find rows in A with NO match in B at all.
-- Employees with NO projects
FROM employees e
LEFT JOIN projects p USING(emp_id)
WHERE p.project_id IS NULL

-- Projects with NO employee (flip FROM)
FROM projects p
LEFT JOIN employees e USING(emp_id)
WHERE e.emp_id IS NULL
💡 Flip FROM table = flip who is the orphan
Aggregate functions
Collapse many rows into one summary. NULLs skipped by default.
COUNT(*) -- all rows incl NULLs
COUNT(salary) -- skips NULLs ✅
COUNT(DISTINCT id) -- unique values only
SUM(salary)
AVG(salary) -- ignores NULLs
MIN(salary) / MAX(salary)

-- NULL-safe total
SUM(COALESCE(salary, 0))
WHERE vs HAVING INTERVIEW
WHERE filters raw rows. HAVING filters aggregated groups.
-- WHERE: filters before grouping
SELECT dept_id, AVG(salary)
FROM employees
WHERE salary > 60000 -- raw rows
GROUP BY dept_id;

-- HAVING: filters after grouping
GROUP BY dept_id
HAVING AVG(salary) > 60000;
💡 Filter uses aggregate? → HAVING. Column filter? → WHERE.
UNION / UNION ALL
Stack two result sets vertically.
-- Remove duplicates (slower)
SELECT name FROM table1
UNION
SELECT name FROM table2;

-- Keep duplicates (faster)
SELECT name FROM table1
UNION ALL
SELECT name FROM table2;

-- Same col count + compatible types
Day 3 — Subqueries & CTEs
Scalar · Correlated · EXISTS · IN · CTEs · Chaining
Scalar subquery
Returns exactly ONE value. Used in WHERE, SELECT, or HAVING.
-- Must return 1 row, 1 column only
SELECT name, salary
FROM employees
WHERE salary > (
SELECT AVG(salary)
FROM employees
);

-- GROUP BY inside = multiple rows = ERROR
⚠ Subquery returns 2+ rows inside WHERE = ERROR always.
Correlated subquery INTERVIEW
Runs once per row. References the outer query column.
-- Above their OWN department average
SELECT name, salary
FROM employees e
WHERE salary > (
SELECT AVG(salary)
FROM employees
WHERE dept_id = e.dept_id ← key line
);
-- e.dept_id is the correlation
IN vs EXISTS INTERVIEW
Both check existence. EXISTS is NULL-safe. Prefer EXISTS.
-- IN: is value in this list?
WHERE emp_id IN (
SELECT emp_id FROM projects
WHERE emp_id IS NOT NULL ← safety
)

-- EXISTS: did any row come back?
WHERE EXISTS (
SELECT 1 FROM projects p
WHERE p.emp_id = e.emp_id ← correlate
)
NOT IN NULL trap ⚠ TRAP
One NULL in subquery list = zero rows returned. Every time.
-- ❌ DANGEROUS if list has any NULL
WHERE emp_id NOT IN (
SELECT emp_id FROM projects
)

-- ✅ SAFE — always add this one line
WHERE emp_id NOT IN (
SELECT emp_id FROM projects
WHERE emp_id IS NOT NULL
)

-- Or use NOT EXISTS (always safe)
⚠ NULL in list → UNKNOWN → every row dropped silently.
CTE — WITH clause
Named subquery on top. Makes complex queries readable.
WITH dept_avg AS (
SELECT dept_id, AVG(salary) AS avg_sal
FROM employees
WHERE dept_id IS NOT NULL
GROUP BY dept_id
)
SELECT e.name, d.avg_sal
FROM employees e
JOIN dept_avg d ON e.dept_id = d.dept_id
WHERE e.salary > d.avg_sal;
Chained CTEs
Each CTE builds on previous. One WITH, comma between CTEs.
WITH cte1 AS (
SELECT dept_id, AVG(salary) AS avg_sal
FROM employees GROUP BY dept_id
),
cte2 AS ( -- can use cte1
SELECT e.name, c.avg_sal
FROM employees e
JOIN cte1 c ON e.dept_id = c.dept_id
)
SELECT * FROM cte2;
💡 Comma between CTEs. Only ONE WITH keyword total.
Day 4 — Window Functions
ROW_NUMBER · RANK · DENSE_RANK · LEAD · LAG · Running Totals · PARTITION BY · NTILE
Window function anatomy
Every window function follows this exact structure.
function_name() OVER (
PARTITION BY col -- like GROUP BY, no collapse
ORDER BY col -- sort within window
ROWS BETWEEN X AND Y -- define frame
)

-- Inside ORDER BY = HOW function calculates
-- Outside ORDER BY = HOW results are displayed
-- They are completely independent
💡 Window functions keep ALL rows — unlike GROUP BY which collapses them.
ROW_NUMBER, RANK, DENSE_RANK INTERVIEW
All three assign numbers to rows. Differ only on ties.
ROW_NUMBER() OVER (ORDER BY salary DESC)
-- Always unique. No ties. Use for deduplication.
-- Ties: Alice=2, Bob=3 (arbitrary order)

RANK() OVER (ORDER BY salary DESC)
-- Ties same rank. SKIPS next number.
-- Ties: Alice=2, Bob=2, next=4 (skips 3)

DENSE_RANK() OVER (ORDER BY salary DESC)
-- Ties same rank. NO skip.
-- Ties: Alice=2, Bob=2, next=3 ✅
💡 Use DENSE_RANK for top-N problems. Never RANK — it skips numbers.
Top-N per group — window version INTERVIEW
LeetCode 185 pattern. DENSE_RANK inside CTE, filter outside.
-- Top 3 earners per department
WITH ranked AS (
SELECT name, dept_id, salary,
DENSE_RANK() OVER (
PARTITION BY dept_id
ORDER BY salary DESC
) AS rnk
FROM employees
WHERE salary IS NOT NULL
)
SELECT name, dept_id, salary
FROM ranked WHERE rnk <= 3;
⚠ Cannot use window function alias in WHERE directly — always wrap in CTE first.
LEAD & LAG INTERVIEW
Look at the next or previous row without a self join.
LAG(salary, 1) OVER (ORDER BY hire_date)
-- salary of previous row (1 row behind)
-- first row gets NULL automatically

LEAD(salary, 1) OVER (ORDER BY hire_date)
-- salary of next row (1 row ahead)
-- last row gets NULL automatically

-- Always wrap in CTE to filter:
WITH cte AS (SELECT ..., LAG(salary,1) OVER(...) AS prev)
SELECT * FROM cte WHERE salary > prev;
Running total & moving average
Use frame clause to define which rows to include in calculation.
-- Running total (cumulative sum)
SUM(salary) OVER (
ORDER BY hire_date
ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
)

-- 3-row moving average
AVG(salary) OVER (
ORDER BY hire_date
ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
)
💡 Frame options: UNBOUNDED PRECEDING · n PRECEDING · CURRENT ROW · n FOLLOWING · UNBOUNDED FOLLOWING
AVG / SUM with PARTITION BY
Aggregate window functions — ORDER BY changes the meaning.
-- Full dept average (NO ORDER BY)
AVG(salary) OVER (PARTITION BY dept_id)
-- Every row in dept gets same avg ✅

-- Running dept average (WITH ORDER BY)
AVG(salary) OVER (PARTITION BY dept_id ORDER BY salary)
-- Each row gets different running avg ⚠

-- Dept running total (resets per dept)
SUM(salary) OVER (PARTITION BY dept_id ORDER BY salary)
⚠ AVG() OVER (PARTITION BY x ORDER BY y) = running avg, NOT full avg.
NTILE, FIRST_VALUE, LAST_VALUE
Divide into buckets, or fetch boundary values within a window.
-- Divide into N equal buckets
NTILE(3) OVER (ORDER BY salary DESC)
-- 1=top tier 2=mid 3=bottom tier

-- Highest salary in each dept (per row)
FIRST_VALUE(salary) OVER (
PARTITION BY dept_id
ORDER BY salary DESC
)

-- LAST_VALUE needs explicit frame:
LAST_VALUE(salary) OVER (PARTITION BY dept_id
ORDER BY salary DESC
ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING)
⚠ LAST_VALUE without explicit frame = wrong result. Always add ROWS BETWEEN.
Window function quick reference
All window functions at a glance with their use cases.
ROW_NUMBER() -- unique row num, no ties
RANK() -- ties same, skips next
DENSE_RANK() -- ties same, no skip ✅
LEAD(col, n) -- n rows ahead
LAG(col, n) -- n rows behind
FIRST_VALUE(col) -- first in window
LAST_VALUE(col) -- last in window
NTILE(n) -- divide into n buckets
SUM / AVG / MIN / MAX() OVER() -- aggregates
Interview Patterns — Day 1 to Day 4
Templates that appear in every SQL interview
Top-N per group (CTE version) INTERVIEW
Highest/lowest per department. Always TWO join conditions.
WITH grp_max AS (
SELECT dept_id, MAX(salary) AS max_sal
FROM employees GROUP BY dept_id
)
SELECT e.name, e.salary
FROM employees e
JOIN grp_max g
ON e.dept_id = g.dept_id ← group
AND e.salary = g.max_sal; ← value
💡 Two ON conditions always: match the group + match the value.
Second highest salary INTERVIEW
Returns NULL automatically if second highest does not exist.
SELECT (
SELECT DISTINCT salary
FROM employees
WHERE salary IS NOT NULL
ORDER BY salary DESC
LIMIT 1 OFFSET 1
) AS second_highest;

-- Outer SELECT returns NULL if inner empty
Every / All pattern INTERVIEW
"Every employee earns above X" — flip to "no one fails".
-- "Every employee earns > 60000"
-- = "No employee earns ≤ 60000"

SELECT dept_id FROM employees
GROUP BY dept_id
HAVING SUM(
CASE WHEN salary <= 60000
OR salary IS NULL
THEN 1 ELSE 0 END
) = 0;
💡 EVERY → flip → NO ONE FAILS → count violators = 0
Date range filter INTERVIEW
Last N days — off-by-one trap catches everyone the first time.
-- Last 30 days INCLUSIVE
WHERE activity_date BETWEEN
DATE_SUB('2019-07-27', INTERVAL 29 DAY)
AND '2019-07-27'

-- N days inclusive = INTERVAL N-1 DAY
-- N days exclusive = INTERVAL N DAY
⚠ 30 days inclusive = INTERVAL 29 DAY not 30.
Employees above own dept avg INTERVIEW
Correlated subquery vs window function — two ways to solve.
-- Way 1: correlated subquery
WHERE salary > (SELECT AVG(salary) FROM employees
WHERE dept_id = e.dept_id)

-- Way 2: window function (cleaner)
WITH cte AS (
SELECT name, salary,
AVG(salary) OVER(PARTITION BY dept_id) AS dept_avg
FROM employees
)
SELECT * FROM cte WHERE salary > dept_avg;
NULL trap master list ⚠ TRAP
Every place NULLs can silently destroy your results.
❌ WHERE col = NULL → use IS NULL
❌ NOT IN (list w/ NULL) → add IS NOT NULL
❌ COUNT(*) for col values → COUNT(col)
❌ SUM(col) with NULLs → COALESCE first
❌ AVG(col) wrong denom → check denominator
❌ ORDER BY with NULLs → NULLs sort first ASC
❌ AVG() OVER(PARTITION BY x ORDER BY y) → running avg!

✅ Always ask: can this column be NULL?
